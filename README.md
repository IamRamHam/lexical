# Lexical

## まず試す人向けの最短手順

1. Windowsで **`Lexicalを起動.cmd`** をダブルクリックします。
2. [Lexical](http://127.0.0.1:4173/) がブラウザーで開いたら、1日の目標を設定してゲストで学習を始められます。
3. 終わるときは、起動時に開いた黒いウィンドウで **Ctrl+C** を押すか、ウィンドウを閉じます。バッチジョブの終了を尋ねられたら、**Y** を入力して **Enter** を押します。

起動には同梱の `dist/` と Node.js 22.13 以降を使います。pnpm・再ビルド・ログインは不要です。Node.jsの案内が表示されたら、公式サイトからWindows用インストーラー（.msi）を入手してインストールし、起動ファイルを開き直してください。 [Node.js 公式ダウンロード](https://nodejs.org/en/download)

起動済みのLexicalがあれば、そのサーバーでブラウザーを開きます。ほかのプログラムがポート4173を使っている場合は、案内に従ってそのプログラムを閉じてから再起動してください。学習の続きは、同じブラウザープロファイルで毎回 `http://127.0.0.1:4173/` を開くと再開できます。ゲスト記録はブラウザーのデータを削除するまで保存されます。

各セットでは選んだ単語を一巡し、その後に間違えた語を順番に解き直します。再度間違えた語は列の末尾に回り、全語に正解すると終了します。中断しても解き直しの順番は保存されます。「今日の学習」や累計には正解した分だけが加算されます。更新前に保存された日別集計は、当時の数値を引き継ぎます。

## 原本と生成データ

| 場所 | 内容 |
| --- | --- |
| `data/source/lexical_words_short_reviewed_v3_1.json.gz` | PCに保持する添付JSONのgzip。展開結果のSHA-256は `data/source/original.sha256` |
| `data/release/site-data.json.gz` | 表示・採点・出典用の生成データ。GitHubのビルドではこちらを使用 |
| `scripts/data.mjs` | 原本から現行の `words.typing_question` を抽出。語義・別解・IDの整合性を検査 |
| `dist/data/catalog.json` | 画面用の単語、短訳、品詞、別解、採点設定、IPA候補 |
| `dist/data/attribution.json` | 出典、使用版、ライセンス、元の統計、表示訳と元訳の由来、編集タグ。出典を開いたときに読み込み |
| `dist/data/build-summary.json` | 原本のハッシュ、抽出件数、IPAの状態別件数 |
| `vendor/phonetic/` | Phoneticからコピーした辞書、音声とライセンス |

登録順とIDを保持し、NGSL 2,809語・TSL 1,250語・SUPPLEMENTARY 52語を出題します。NGSLとTSLは各リスト内の頻度順位を5等分して星を付けます。範囲番号はリストと重要度を絞り込んだ後の登録順です。SUPPLEMENTARYの星は空欄です。

生成時は99,461,068バイトの原本から表示用カタログ約2.8 MBを生成します。原本の訳・語義・履歴は書き換えていません。採点では、原本で許可された大小文字・記号・アクセントの差に加えて、今回の仕様で入力の前後の空白を無視します。語中空白と活用形は保持します。使用版と訳の加工区分は各単語の「この単語の出典」で確認できます。データを再配布するときは同梱の帰属情報と、CC BY-SA 4.0など各出典の条件を引き継いでください。

原本を再取り込みするときは `node scripts/import-source.mjs "原本.jsonのパス" "Phoneticフォルダーのパス"` を実行し、`pnpm data:release` で公開用データを更新します。外部原本を試験ビルドするときは環境変数 `LEXICAL_WORDS_ORIGINAL` も指定できます。

## 発音

Phoneticの `pronunciations.js` と `dictionary.js` で、ビルド時に米語のIPAを生成します。原本に確認済みの米語IPAが追加された場合はそちらを優先できます。現行原本からは辞書候補1件が3,379語、候補複数が719語、分割変換などの追加確認が必要な候補が6語、未収録が7語です。`read` や `lead` などは候補を示し、語義と発音の対応は要確認と表示します。アクセントを落とす辞書検索では `résumé` と動詞 `resume` の候補が同じになる場合があります。学習の単語IDと正答表記は原本のままです。

発声はPhoneticの `fallback-speech.js` と同梱PicoVoxモデルを再利用します。モデルの読み込み先はサイト内の `english-voice.js` です。自動再生は学習開始・再開や答えを見る操作で音声を解放してから行います。PicoVoxが使えないときは、端末が提供するローカル米語音声があれば再生できます。音声は見出し語のみを読むため、語義によって読みが変わる単語では、再生された音が特定の語義に対応するとは限りません。

Phoneticの実ファイルがある環境では、ビルドが元のHTML・CSS・素材を `dist/phonetic/` にコピーします。ヘッダーからそのコピーを開けます。公開時は実際のPhonetic公開URLを `LEXICAL_PHONETIC_URL` に設定できます。公開URLも元ファイルも設定されていない環境では、ヘッダーのPhoneticリンクを非表示にします。

## SupabaseとGoogleログイン

[公開とGoogleログインの手順](DEPLOY.md)に、SupabaseでのSQLの適用、Googleの認証設定、GitHub Pagesへの接続、既存のゲスト記録の取り込み方法をまとめています。

DBはユーザー単位の設定とセット、単語×回答方法の進捗、日別回数、共通の苦手タグを保存します。RLSは自分の行だけを読めるようにし、書き込みはログイン中のIDを検証するRPCで行います。コミットはユーザー行をロックし、更新番号が合う操作だけを反映します。再試行用の端末別の最終連番と、取り込み済みゲストIDを保持します。回答ごとの永続履歴は作成していません。 [SupabaseのRLS](https://supabase.com/docs/guides/database/postgres/row-level-security)

ブラウザはIndexedDBにゲスト記録と未確定の送信を保存します。同期に失敗した場合は再試行が表示され、保存が確認できた時点で回答結果へ進みます。ゲスト取り込みでは、回数を加算して、同じ単語・回答方法の習得度や復習予定は最終回答が新しい側を採用します。同時刻はアカウント側です。設定は最後の変更が新しい側です。アカウントに途中のセットがあれば優先し、空いていればゲストの途中セットを引き継ぎます。

## 復習とレベルの暫定設定

設定値は `src/rules.mjs` で変更できます。原論文は、最終練習からの経過時間を `Δ`、半減期を `h` としたときの想起確率 `p = 2^(-Δ/h)` を用い、学習履歴からモデルの重みを推定しました。Lexicalはこの減衰式を使い、回数と連続正誤数から手作業で決めた固定係数で半減期を算出します。 [Settles & Meeder, ACL 2016, §3.3](https://aclanthology.org/P16-1174/)

- 時間の単位は秒です。初回正解の半減期は24時間で、目標想起確率80%に達する約7時間44分後を次回復習とします。
- 正解時は、累計正解・累計不正解を上限512回として対数で取り込み、正解の連続は最大8回分を反映します。不正解時は45分の半減期を基準に、連続不正解に応じて縮めます。
- 半減期は20分〜180日、復習間隔は5分〜30日です。未学習の単語には半減期も想起確率もありません。係数の自動学習や新たな分析用履歴の追加はありません。
- 習得度バーの増減と30日経過による習得済み解除は、復習時刻とは独立しています。学習日は日本時間午前5時に変わります。レベルは累計の学習量が100語分増えるごとに1上がり、初期値は1です。

## 公開する

[Lexicalの公開と更新](DEPLOY.md)を上から進めてください。GitHub Pagesの公開元をGitHub Actionsに設定すると、`main` へのPushでビルド・検査・公開が実行されます。ブラウザーには生成済み `dist/` を配信します。

ヘッダー・フッターのロゴは [public/lexical-logo.png](public/lexical-logo.png)、タブのアイコンは [public/book.svg](public/book.svg) を編集します。`pnpm build` でPCの起動版に反映できます。

## 開発者向けの起動手順

Lexicalフォルダーで、ロックファイルに沿って依存関係を用意し、ソースからビルドします。

```sh
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

`pnpm dev` は生成後にローカルサーバーを起動します。設定を変えた場合は再実行してください。ビルド済みサイトをターミナルから配信するだけなら `node scripts/serve.mjs` で起動できます。開発時のみ別のポートを使うときは `node scripts/serve.mjs 4174` のように指定できます。

## 検証結果と接続状況

- Windowsの起動ファイルで、日本語・空白のあるフォルダーからの起動、既存サーバーの再利用、ポート競合、Node.jsが見つからない場合の案内を確認しました。固定URLでサーバーを起動し直した後も、ゲストの目標・回答数・ランダム出題順を保持して再開できました。

- `pnpm build` と `pnpm check` に合格。4,111語のID、表示順、語義、別解、星、出典の参照を確認しました。原本なしの公開用データで再ビルドし、`/lexical/` 配下での画面表示と、Google認証に渡す戻り先URLもローカルで確認しました。
- `pnpm test` の14テストに合格。3方式の分離、正解だけの日別加算、解き直しの順番、旧セットの引き継ぎ、習得度・不正解解除・30日解除、推薦順、表記差などを検証しました。ローカルPostgreSQL（PGlite）でマイグレーションを適用し、RLS、他人のIDを指定したRPCの拒否、登録済み回答と取り込みの重複防止を確認しました。
- EdgeのPC幅1440pxとスマートフォン幅390pxでブラウザ操作を検証しました。3方式、空欄、IME中のEnter、回答時の表示順、解き直しの再開、音声再生、タグ・検索・出典、複数タブからの二重回答防止を確認しました。模擬ログインと実SQLを組み合わせて、通信応答を失った直後の再試行と、ゲスト取り込みの再実行も確認しました。
- ブラウザテストを再実行するにはPlaywrightを開発環境に用意します。ローカルサーバー起動中に `pnpm test:browser` を実行します。Edgeを既定とし、`LEXICAL_BROWSER=chrome` でも実行できます。別ポートは `LEXICAL_TEST_URL` で指定できます。
- Google OAuthと実際のSupabaseプロジェクトには接続設定が必要です。実機iPhone Safariの音声、公開先URLでのOAuth、GitHub Pagesのデプロイは未確認です。
